## 1. Как развернуть

```bash
tar -xzf viart-site.tar.gz     # распаковать
cd viart-site
npm install                    # поставить зависимости по package-lock.json
npm run dev                    # открыть http://localhost:3000
```

`npm install` ставит ровно те версии, что зафиксированы в `package-lock.json`,
поэтому `node_modules` в архиве нет — он воспроизводится байт в байт.

Проверить, что распаковалось всё и без повреждений:

```bash
./проверить.sh
```

Скрипт сверяет каждый файл с контрольной суммой SHA-256 из `SHA256SUMS.txt`.
Строка `ВСЁ СОВПАДАЕТ` означает стопроцентную идентичность оригиналу.

## 2. Что сказать новой сессии

Скопируйте это сообщение целиком первым сообщением в новой сессии:

> В архиве `viart-site.tar.gz` лежит готовый сайт студии ViART на Next.js —
> исходники, все фотографии и видео. Распакуй его, поставь зависимости
> (`npm install`) и запусти (`npm run dev`). Ничего не переписывай и не
> создавай заново: сайт уже собран, задача — развернуть его как есть.
> В корне проекта лежит `CLAUDE.md` с правилами проекта, прочитай его до
> первой правки. Проверить целостность распаковки можно скриптом
> `./проверить.sh`.

## 4. Три вещи, которые нельзя нарушить

Ими держится идентичность. Подробнее — в `CLAUDE.md` и в комментариях внутри
самих файлов (код прокомментирован очень плотно, там записаны причины решений).

1. **Текст живёт только в `content/viart.ts`.** Компоненты не содержат строк.
2. **Цвет живёт только в `app/globals.css`.** Ни один компонент не называет
   оттенок напрямую — всё идёт через переменные и Tailwind.
3. **Отзывы — дословные цитаты с Яндекс Карт.** Их не редактируют и не
   сочиняют; факты (цены, часы, адрес, рейтинг) — тоже настоящие.

## 5. Если понадобится история изменений

Отдельным файлом идёт `viart-git-history.bundle` — полная история из 22
коммитов. Он **не нужен** для запуска сайта, только для просмотра, как
проект развивался:

```bash
git clone viart-git-history.bundle viart-repo
cd viart-repo && git log --oneline
```

Если бандла под рукой нет — ничего не теряется: рабочее дерево в архиве уже
и есть последнее состояние проекта.
