# ViART — правила проекта

Сайт студии лазерной эпиляции и аппаратного массажа ViART (Москва, Коммунарка).
Готовый, работающий проект. Прочитай этот файл до первой правки.

## Стек

Next.js 16.3.3 (App Router, Turbopack) · React 19 · TypeScript 5.7 ·
Tailwind 3.4. Ни базы, ни API, ни серверных действий: `next build` отдаёт все
маршруты статикой. Онлайн-запись — внешняя ссылка на YClients.

```bash
npm install     # строго по package-lock.json
npm run dev     # http://localhost:3000
npm run build   # прод-сборка; она же проверяет типы
npx tsc --noEmit
```

## Маршруты

| Путь | Что это |
|---|---|
| `/` | главная — 12 полос (bands) |
| `/masters` | страница мастера |
| `/faq` | вопросы и ответы |
| `/rose`, `/rose/masters`, `/rose/faq` | те же страницы во второй палитре |

`/rose` — не копия. Это те же компоненты, ре-экспортированные под путём, на
который `lib/theme.ts` вешает `data-theme="rose"` на `<html>`. Одна кодовая
база, покрашенная дважды. Страницы `/rose` закрыты от индексации.

## Четыре правила, на которых всё держится

**1. Текст — только в `content/viart.ts`.**
Компоненты не содержат ни одной строки копирайта. Меняешь текст — правишь этот
файл, и больше ничего. Там же цены, отзывы, контакты, заголовки полос.

**2. Цвет — только в `app/globals.css`.**
Каждый оттенок сайта — это тройка каналов в `:root` (и её вариант под
`[data-theme="rose"]`). `tailwind.config.ts` привязывает к ним всю палитру
через `rgb(var(--token) / <alpha-value>)`, поэтому `bg-lav`, `text-white/72`
и `border-gold/30` перекрашиваются от одной правки переменной. Компонент
никогда не называет оттенок напрямую — ни хекса, ни `rgba()`.
`text-white` в этой теме — тёплые сливки `#f4ecd8`, а не белый.

Прозрачности ink взяты из фиксированной лестницы (100 → 92 → 88 → 84 → 80 →
76 → 72 → 68 → 62 → 58 → 54 → 48), она записана и обоснована в шапке
`globals.css`. Ниже 48 не опускаться: если строка не стоит контраста 4:1, она
не стоит того, чтобы её набирать.

**3. Отзывы — дословные цитаты.**
`reviews.items` и `reviews.more` — реальные отзывы с Яндекс Карт, приведённые
буква в букву, с опечатками и эмодзи авторов. Не редактировать, не
приглаживать, не сочинять новые. Факты (цены, часы, адрес, рейтинг 5,0 · 98
отзывов · 119 оценок · «Хорошее место 2026») — тоже настоящие, сверены с
карточкой организации.

**4. Медицинских обещаний нет.**
Нигде не утверждается «удалим навсегда», не приводятся сертификаты и
клинические результаты. Говорится только о том, каким будет визит.

## Как устроена главная

Одна сплошная тёмная комната, а не стопка полос. Фон — `AmbientField`, одна
поверхность на весь сайт; глубина берётся из размытых пятен света без границ,
а не из панелей разного тона. Отсюда три правила вёрстки:

- заголовок полосы всегда по центру и всегда одно предложение — без нумерации,
  без кикеров, без второй гарнитуры;
- плиточный контент — квадратная картинка с подписью не шире квадрата;
- ничего не едет само по себе, кроме фоторельса, и тот замирает от касания.
  Бегущих строк на сайте нет.

Порядок полос и анимация каждой описаны в шапке `app/page.tsx`.

## Система анимаций

Серверная разметка плюс CSS, почти без клиентского кода.

- `components/motion.tsx` — `Reveal` (клиентский): ловит попадание в экран и
  ставит детям `data-shown` с шагом `step`. Там же `CountUp`, `Accordion`,
  `Parallax`, `StickyCta`.
- `components/m.tsx` — `M`: чистая разметка без хуков, берёт сигнал от
  `data-shown` родителя. 17 вариантов: `rise`, `fade`, `deal`, `zoom`, `pop`,
  `wipe`, `curtain`, `draw`, `fromLeft`, `fromRight`, `flip`, `settle`,
  `aperture`, `focus`, `drawCenter`, `drawY`, `none`.
- сами переходы — в `app/globals.css` по селекторам `[data-m="…"]`.
- `lib/motion.ts` — наблюдатель и `MOTION_BOOTSTRAP`, который ставит
  `data-motion="on"` до первой отрисовки. При `prefers-reduced-motion` вся
  система выключается целиком.

Добавляя движение, бери существующий вариант `M`. Новый заводи, только если
ни один не подходит, и клади его туда же, в `globals.css`.

## Компоненты

`ui.tsx` — каркас: `Band` (полоса + пятно света), `SectionHead` (черта,
заголовок, лид), `Button`, `Heading`, `MediaTile`, `Card`, `PageHeader`.
`HeroStage` — первый экран с шестью медиа-квадратами. `VideoTile` — вертикальный
ролик со своим звуком и постером. `StoriesRail` — фоторельс с лайтбоксом.
`PriceMenu` — прайс: два переключателя (кому / что смотреть) над прокручиваемым
списком. `MediaFrame` — кадр с фиксированной пропорцией. `Header`, `Footer`,
`AmbientField`, `AmbientVideoGuard`, `HeroScatter`, `ThemePreset`.

Ловушка в `PriceMenu`, записанная в самом файле: вкладки переключаются тем,
что неактивные панели **не рендерятся**. Атрибут `hidden` здесь не работает —
это `display: none` от браузера, и любой авторский `display` его перебивает.

## Телефон — не второстепенный случай

Половина решений в коде принята ради узкого экрана, и это записано рядом с
кодом. Три ролика в ряд на 390px дают по 117px — поэтому ниже `md` ряд
становится свайп-лентой. Три вкладки прайса не помещались в строку — поэтому у
каждой есть короткая подпись для телефона (`short` в `pricing.views`), а строка
делится на равные колонки. Проверяй правки на 320, 360 и 390 px.

## Стиль кода

Комментарии в проекте объясняют **почему**, а не что: что пробовали, почему
отказались, чем это кончилось для читателя страницы. Держи эту планку — она
здесь дороже краткости. Комментарии в коде на английском, тексты сайта и
сообщения коммитов — на русском.
